# AI提示词共享库（Prompt Palette）

> 【共享库作者为graceshen/codex/deepseek/claude，开源项目，不收费，如有人以不同形式复传盗卖共享库核心功能，请立马退款，并搜索免费版下载，codex/workbuddy插件搜索（AI提示词共享库/AI Prompt Shared Library），其他渠道github搜索以上关键词让agent协助下载安装，我们这个项目主旨是普惠大众，共享便利】

## 用途

人的需求往往是模糊的。这个技能的目标是：**agent 干活前自己先查提示词库**，把最合适的任务提示词（角色设定、执行步骤、输出格式）当作自己的工作协议，从而比“用户手写需求”更精细化地完成任务；同时保留用户主动调用、管理、导出、同步提示词的能力。

## 数据文件

- 内置数据：`../../assets/prompts.json`（相对本 SKILL.md；若相对路径解析失败，用 PowerShell 在当前插件安装目录的 `assets` 下查找）
- 用户数据：默认 `Documents\Codex\prompt-palette-data\user-prompts.json`（Windows，不存在则创建；其他系统为 `~/.prompt-palette/`；可用环境变量 `PP_DATA_DIR` 覆盖；格式：`{"version":1,"updatedAt":"...","customs":[{"id":"c-...","c":"分类","t":"标题","tags":[],"p":"内容"}],"favorites":[]}`）
- 检索脚本：`../../assets/search_prompt.mjs`（推荐用脚本检索，结果快且确定）
- 本地服务：`../../assets/server.mjs`（随插件自带，检索脚本会自动拉起；默认端口 1190，占用时自动换端口，运行信息写入用户数据目录的 `server-info.json`）；检索脚本还会按需静默拉起 DeepLX（1188）与翻译代理（1189），无窗口后台运行。
- 独立 UI：`../../assets/AI提示词工作台.html`（网页版，支持社区共享库、GitHub Gist 云同步、全量库导入、一键翻译、文档/图片导入）
- 内置 JSON 结构：数组，每项 `{id, c, t, tags, p}`；`c` 分类键：`meta` 通用/元提示词、`dev` 编程开发、`write` 写作、`art` 美术/设计、`fin` 金融/投资、`data` 数据分析
- 内置第一条 `meta-1` 是“需求转提示词（最常用）”：把模糊需求改写成结构化提示词（角色、目标、输入、步骤、约束、输出格式）。

## 自动匹配（无需用户主动调用，本技能的核心）

**任何常见任务开始前，先按用户配置决定是否检索提示词库；检索后先征得同意，再把最匹配的提示词当作执行协议。** 具体流程：

1. 先读配置 `<用户数据目录>/agent-match-config.json`（不存在则按默认：`enabled=false, confirm=true, asked=false, maxTokens=2000, maxCostCny=0.05, pricePerMTokCny=2`）。`enabled=false` 时**不自动检索**；仅当 `asked !== true`（从未问过）时，**首次调用本插件时询问一次是否开启自动匹配**：“本插件内置提示词自动匹配（默认关闭）：开启后我会在做编程/写作/美术/金融/数据分析等任务前，自动检索提示词库并先征得你同意再套用，每次约 1 千 token、不到一分钱。是否开启？”**问完无论同意还是拒绝，都必须把 `asked` 写为 `true`**：用户同意 → 把 `enabled` 改为 `true`（并保留 `confirm=true`）；用户拒绝 → `enabled` 保持 `false`，直接按用户原话执行。**之后任何会话（新开会话、再次打开插件）都不再重复询问**：`asked=true` 且 `enabled=false` 时静默关闭，直接执行用户需求，不打扰用户。
2. 判断任务类型（编程/写作/美术/设计/金融/数据分析/通用），提取关键词（如“SQL”“周报”“配色”“财报”“回归分析”）。
3. 运行检索脚本（优先）：
   - `node "../../assets/search_prompt.mjs" "关键词" --limit 3 --estimate`（若相对路径不可用，用 PowerShell 在插件 assets 目录下查找脚本；脚本首次运行会自动拉起内置本地服务，无需用户手动开服务）
   - 需要限定分类时加 `--category dev|write|art|fin|data|meta`
   - 脚本同时检索内置库和用户自定义库，支持错字容错、缩写、多关键词；**默认只列标题，不输出正文**，节省 token。
4. **征得同意（confirm=true 时必做）**：把候选标题展示为可点击链接（`search_prompt.mjs` 输出的就是完整 Markdown 链接，形如 `http://127.0.0.1:<端口>/app?prompt=<ID>`，端口由内置服务自动分配），点击后会在本地 HTTP 服务里打开工作台并定位展开对应提示词卡片，用户可先看完整正文再决定。同时给出 `--estimate` 的预估（约 N token ≈ ¥M），问“是否用【XX】提示词的框架执行？”。用户同意（“用/可以/好的”）后才执行下一步；用户拒绝则按原话执行。`confirm=false` 时跳过询问，但要先口头说明将使用哪个提示词，并同样附上可点击链接。**若本地服务启动失败或链接打不开**，直接用 `search_prompt.mjs "标题" --full --limit 1` 把完整正文贴进对话给用户看。
5. **预算控制**：预计总 token 超过 `maxTokens` 或金额超过 `maxCostCny` 时，不自动套用，只提示“超出预算未套用，可提高预算或手动指定”。未超出才继续。
6. 有匹配且预算内：取评分最高的 1 条（必要时 2 条组合），用 `--full --limit 1` 只读取这一条全文，**把其中的角色设定、执行步骤、约束和输出格式作为本次任务的执行框架**。
7. 无匹配或用户需求模糊：使用 `meta-1`“需求转提示词”模板，把用户的目标改写成结构化提示词（角色/目标/输入/步骤/约束/输出格式），先复述目标和验收标准；如果关键信息缺失，只问 1 个最关键的问题，其余按合理默认执行，不要连环追问。
8. 执行时严格按提示词框架输出（结构、清单、格式），而不是自由发挥；任务结束后，如果用户同意，可把本次打磨出的高质量任务模板作为新提示词存入用户库（见“用户自定义提示词”）。

## 配置与预算（节省 token）

- 配置文件：`<用户数据目录>/agent-match-config.json`
- 用户可以直接用自然语言改配置，Codex 用 PowerShell 以 UTF-8 无 BOM 写回（写前读、写后校验）：
  - “关闭自动匹配” → `enabled=false`
  - “重新开启自动匹配” → `enabled=true`（同时写 `asked=true`，不再重复首次询问）
  - “以后不要再问自动匹配 / 我已经拒绝过了” → 确保 `asked=true` 且 `enabled=false`（首次询问后会自动记录，无需用户再操作）
  - “以后自动匹配不用每次问” → `confirm=false`
  - “每次都要问” → `confirm=true`
  - “预算提高到 5000 token / 0.1 元” → 修改 `maxTokens` / `maxCostCny`
- **压缩读取铁律**：候选阶段只读脚本输出的标题行；套用阶段只读 1 条全文；不要把整个 `prompts.json`、用户库或社区库打印/朗读到上下文；预估费用时以 `search_prompt.mjs --estimate` 的结果为准，不要自己重新统计全文。

## 用户主动调用

1. 解析用户意图：提取关键词（如“SQL”“周报”“配色”“财报”）和/或分类（编程/写作/美术/金融/数据/通用）。
2. 优先用 `search_prompt.mjs` 检索；脚本不可用时再手工读取 `prompts.json` 和用户数据文件的 `customs` 合并搜索：对标题、标签、内容做不区分大小写包含匹配；多个关键词全部命中才保留；用户指定分类时按 `c` 过滤。
3. 展示结果：最多 5 条，按“标题（分类）— 标签”列出，附一句内容提示。用户未明确选择时，默认选第一条最匹配的并说明。
4. 复制到剪贴板（Windows）：用 PowerShell `Set-Clipboard` 写入提示词全文。构造命令时用单引号包裹提示词文本，并把文本内部的单引号翻倍（`''`）转义，避免命令出错。
5. 执行后告知“已复制 ✓，去粘贴即可”，同时在对话中完整展示该提示词，方便用户核对或手动复制。
6. 若无匹配：如实告知未找到，建议打开 `assets/AI提示词工作台.html` 搜索，或提供“需求转提示词”模板（`meta-1`）改写需求。

## 打开工作台（内置浏览器优先）

- 用户说“打开提示词库 / 打开 AI 提示词共享库 / 打开工作台 / 打开网页版”时，**优先用 Codex 内置浏览器打开本地服务地址（`http://127.0.0.1:<端口>/app`）或本插件 `assets/AI提示词工作台.html`**；不要调用系统默认浏览器（不要用 `start`、`explorer`、`open` 等拉起电脑自带浏览器）。
- 若当前环境无法使用内置浏览器，把本地地址直接告诉用户，并说明可以用 Codex 内置浏览器打开，或由用户自行复制到浏览器。
- 只有用户明确说“用电脑自带浏览器 / 用默认浏览器打开”时，才使用系统默认浏览器打开。

## 用户自定义提示词

- 用户说“新增提示词 / 保存这个提示词 / 存为我的提示词”时：先读取用户数据文件（不存在则初始化），在 `customs` 末尾追加 `{id:"c-"+时间戳, c:分类, t:标题, tags:标签数组, p:内容}`，再用 PowerShell 以 UTF-8 无 BOM 写回整个文件（写前读、写后校验，避免覆盖）。
- 用户说“列出我的提示词 / 删除提示词”时：同样先读文件再写回；删除前与用户确认。
- 用户说“导出提示词”时：默认导出为 CSV（`act,prompt` 两列，兼容 Excel / prompts.chat）和 Markdown（分类分章，可直接粘贴到任何 AI 工具），文件放到用户桌面或指定目录，文件名含日期。

## 翻译

- 内置翻译只覆盖常见提示词；遇到冷门英文提示词，Codex 直接把它翻译成中文（标题+正文）并展示，翻译结果可作为新提示词保存到用户库。
- 若本机已安装 muyi-translate 技能（个人插件），优先按 muyi-translate 的工作流翻译：快速/标准/精修模式、术语一致、保留 Markdown 结构；用户说“精翻/高质量翻译”时必用精修流程。
- 网页工作台里的“译”按钮走本地代理通道（DeepSeek/百度/Google/MyMemory）并缓存，冷门词也能看懂；它无法直接调用 muyi-translate（该插件是 Codex 技能，无 HTTP 接口）。

## 公网云同步（GitHub Gist）

- 网页工作台已内置 Gist 同步：填写 GitHub Token（只需 gist 权限）→ 上传到云端；之后修改自动同步；换电脑后同一 Token 点“从云端下载”恢复。
- 社区共享库（母库+子库）可直接下载使用，不需要登录 GitHub；上传/创建子库需要账号和 Token。
- 社区共享库的 Gist ID（母库/子库/我的库）只允许 20-32 位十六进制字符；用户提供其他格式（如完整 URL 或带空格/符号的文本）时，提示复制完整 Gist ID 或检查链接。
- Codex 侧：若用户提供了 Gist Token 和 Gist ID，可以用 PowerShell 调用 GitHub API 上传/下载用户数据文件（`PUT/PATCH /gists/{id}`，文件名为 `user-prompts.json`）。不要把 Token 写进插件文件，仅在本次对话中使用。

## 常用说法示例

- 用户说“帮我写个周报/做个 SQL 优化/画个海报/分析下这个数据” → 自动先检索对应提示词再执行（无需用户提“提示词”二字）。
- “调用提示词：SQL 优化”
- “给我一个写周报的提示词”
- “新增一个提示词：……，分类写作文案”
- “把刚才那个提示词存到我的库”
- “导出我的提示词为 CSV 和 Markdown”
- “这个英文提示词帮我翻译成中文（用精翻）”

## 注意

- 写用户数据前先读现有文件，避免覆盖其他内容。
- 剪贴板复制失败时，至少把完整提示词文本输出在对话里。
- Gist 同步只上传用户自定义数据，不包含内置库。
- 自动匹配失败或用户明确不要提示词框架时，直接按用户原话执行，不要强加模板。
